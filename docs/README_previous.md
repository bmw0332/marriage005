## 設計方針

**「自分に合う相手が見つかりそう」→「相談したい」** を最短で成立させる順序にしました。

1. **ヒーロー** — 症状を言い当てる（なかなか会えない／続かない）
2. **2択** — 自分はどちらかを選ばせ、当事者にする
3. **出会いの母数** — 「結婚を考えている人が11万人」。ここで**相手が見つかりそう**と感じてもらう
4. **進め方** — 見つけた後どうするか。手順と支援範囲
5. **実績** — 本当にできるのか。数字＋設計者
6. **事例** — 自分と同じ状態から変わった人がいる
7. **料金** — いくらか
8. **向き不向き〜FAQ〜最終CTA** — 最後の不安を消す

旧版は 悩み → 原因 → IBJ → Before/After → メソッド → 支援内容 と、**解決策に入るまで6セクション**かかっていました。新版は3つ目でIBJの母数、4つ目で支援内容に到達します。

GA4・GTM・ClarityのIDを入れると読み込まれます。空欄なら外部スクリプトは一切読み込みません。

canonical と og:url の2箇所。**LP内で唯一残っているプレースホルダーです。**

- **事例**：`CASES` 配列。`consent: true` のカードのみ表示されます

### 配置：支援内容と実績のあいだ

```
支援内容（何をするか）
   ↓
★ 設計した理由（なぜやるか）  ← 新設
   ↓
実績（本当にできるのか）＋ 設計した人
   ↓
事例（実際どうなったか）
```

**「何を」→「なぜ」→「できるのか」→「実際どうか」** という順序にしました。手法の説明（支援内容）の直後に理由を置くことで、それまで読んできた手順が「なぜこの形なのか」の答えとして回収されます。そのうえで実績・経歴・事例と、裏づけが続く構成です。

料金の直前ではなく実績の前に置いたのは、**熱量を先に伝えてから残りを読ませたい**ためです。金額の直前だと、感情に訴えて判断を鈍らせる印象になりかねません。

- 背景はウォームホワイト。前後が白と濃紺のため、**個人の語りとして浮き立ちます**

「他社より高めですが」を削り、「初期費用に何が含まれるか」だけを述べる形に変更することをおすすめします。事実と異なる価格帯の主張は、景品表示法の観点からも避けたほうが安全です。

**② キャンペーンカードとの関係**

カードに「期間限定で初期費用を優待しています」と記載しています。今回の128,000円が**改定後の通常価格**なのか、**優待適用後の価格**なのかによって、表記の扱いが変わります。

優待後の価格を表示する場合、通常価格を併記すると二重価格表示となり、景品表示法上の制約を受けます。「128,000円は通常価格で、優待はそこからさらに割引」という運用であれば現状のままで問題ありません。


原因は、節を分割する正規表現の区切り文字に**中黒（・）を含めていた**ことです。

```js
/* 修正前 */ var PW_SPLIT = /[^、。！？・：；]*[、。！？・：；]+/g;
/* 修正後 */ var PW_SPLIT = /[^、。！？：；]*[、。！？：；]+/g;
```

中黒は、句読点よりも**複合語をつなぐ用途**で使われることが多い記号です。「クーリング・オフ」のような法律用語を分断していました。

```js
[ァ-ヶ][ァ-ヶー]*(?:・[ァ-ヶ][ァ-ヶー]*)+
```

これにより「クーリング・オフ」が3ファイルすべてで1つの不可分な単位として扱われます。契約条件に関わる用語のため、影響の大きい修正です。

## Ver 4.8.0 の変更点

Ver 4.7.0ではCTA補足文8か所を手作業で直しましたが、同じ問題が本文全体にありました。**個別対応をやめ、仕組みで解決しています。**

### 仕組み

ページ読み込み時に、本文（`main` 内の `p` `li` `dd` とフッター注記）の改行位置を自動で整えます。

**① 句読点で区切る**

`、。！？・：；` の後ろで文を分割し、各断片を `display:inline-block` の `span` で囲みます。囲まれた内側では改行が起きないため、**節の途中で割れなくなります**。

改行位置を強制するのではなく、不自然な位置での改行を禁止する仕組みです。画面が広ければ複数の断片が同じ行に並びます。

**② 語のかたまりを保護する**

断片の内側で、次のパターンを `white-space:nowrap` で保護します。

| 対象 | 例 |
|---|---|
| カタカナ語（2文字以上） | ポイント、コーディネート、スタイリスト |
| 英数字 | LINE、IBJ、GU |
| 数量表現 | 30分、165,000円、6か月、33項目、23名 |

「ポ／イント」のような分割が起きなくなります。

**③ 長い節を助詞で二次分割**

句読点のない16文字超の節は、助詞（を・に・へ・は）の後ろでさらに分割します。ただし直後が活用語尾または複合助詞の場合は分割を見送ります。

```js
/([^、。！？]{5,}?[をにへは])(?![らりるれろっずぬま]|もと|はじめ|つい|おい|おけ|…)(?=[^、。！？]{5,})/g
```

この除外がないと「か／ら」「な／がら」「6か／月」「条件を／もとに」のように壊れます。**除外条件を入れる前は、複合助詞を割る箇所が7件発生していました。**

### 限界について

残る31断片は、句読点も対象助詞も含まない長い文です。ここは従来どおり文字単位で折り返しますが、**カタカナ・英数字・数量表現は保護されるため、目立つ割れ方はしません**。漢字とひらがなの途中での改行は、日本語組版では通常の挙動です。

完全な文節解析を行うには形態素解析ライブラリ（BudouXなど）が必要で、20KB前後の追加になります。現状の方式は追加0KB（スクリプト内に約40行）で、目に見える問題は解消できています。

- `try/catch` で囲んでいます。万一エラーが起きても、本文は元のまま表示されます
- `createTreeWalker` `getComputedStyle` が使えない環境では処理をスキップします

## Ver 4.7.0 の変更点

CTAの補足文が「見直すべきポ／イントが分かります」のように**カタカナの途中で割れていた**問題を修正しました。

### 原因

Ver 3.16.1で追加した `overflow-wrap: anywhere` です。

```css
/* Ver 3.16.1（不具合あり） */
body{ word-break:normal; line-break:strict; overflow-wrap:anywhere; }
```

`anywhere` は「**どの2文字の間でも改行してよい**」という指定です。長いURLがはみ出すのを防ぐつもりで入れましたが、日本語の本文に適用すると単語の途中で平然と割れます。「ポイント」が「ポ」と「イント」に分かれたのはこのためです。

### 修正内容

**① `anywhere` を `break-word` に変更**

```css
body{ word-break:normal; line-break:strict; overflow-wrap:break-word; }
```

`break-word` は「その語を切らないと行から溢れる場合にだけ」割ります。通常の日本語の文では発動しません。長いURLへの対策は維持されます。

**② CTA補足文8か所に `pw`（文節改行）を適用**

`overflow-wrap` の修正だけでは、ブラウザによってはカタカナ内で改行される可能性が残ります。確実にするため、既存の `pw` の仕組みを使って**句読点でのみ折り返す**ようにしました。

```html
<p class="cta-note pw"><span>5問の質問に答えるだけで、</span><span>いま最初に見直すべきポイントが分かります。</span><span>面談予約は必須ではありません。</span></p>
```

`.pw > span{display:inline-block}` により、**spanの内側では改行されず、spanとspanの間でのみ改行**されます。改行位置を強制するのではなく、不自然な位置での改行を禁止する仕組みです。画面が広ければ複数のspanが同じ行に並びます。

### 320px端末での検証

分割した全16断片が、最も狭い320px幅（使える幅288px）に収まることを確認しました。最長は「いま最初に見直すべきポイントが分かります。」の約262pxです。

### 変更内容

| | 挙動 |
|---|---|
| 変更前 | ページを開いた時点から追従CTAが常時表示 |
| 変更後 | ヒーローCTAが見えている間は非表示。スクロールして画面外へ出た時点で、下からせり上がって表示 |

**最終CTAセクションでも同じ制御を入れています。** ページ末尾では「30分の無料個別診断を予約する」ボタンが画面内にあるため、ここでも追従CTAは引っ込みます。指摘いただいた重複はファーストビューだけでなく、ページ末尾でも起きていました。

### 実装

```css
.sticky{ transform:translateY(100%); opacity:0; visibility:hidden;
         transition:transform .28s ease, opacity .28s ease, visibility .28s }
.sticky.is-on{ transform:translateY(0); opacity:1; visibility:visible }
```

`IntersectionObserver` で `#cta-timerex-hero` と `#cta-timerex-final` を監視し、**どちらも画面外にある時だけ** `is-on` を付けています。`display:none` ではなく `transform` と `opacity` で切り替えているため、GPU処理でスクロール中も滑らかに動きます。

- **`prefers-reduced-motion`**：OS側で視差効果を減らす設定にしている方には、アニメーションを実質無効化しています
- **`visibility:hidden`**：非表示中はスクリーンリーダーとキーボード操作の対象から外れます。`opacity:0` だけでは、見えないボタンにフォーカスが当たってしまいます
- **フォールバック**：`IntersectionObserver` が使えない環境、または監視対象が見つからない場合は、従来どおり常時表示になります。追従CTAが出ないという事故は起きません
- `body` の `padding-bottom:78px` は維持しています。追従CTAが出た際に、フッター末尾がボタンの下に隠れるのを防ぐためです

### ② 変な改行の原因と修正

原因は本文の文字列ではなく、CSSの `word-break: auto-phrase` でした。

```css
/* 修正前 */
body{ word-break:auto-phrase; }
```

`auto-phrase` は日本語を**文節単位で折り返す**指定です。見出しのような短い文では自然に見えますが、本文のような長い文に使うと「文節の途中では絶対に折り返さない」ため、行末に大きな余白が生まれます。

Q14の場合、`「会った後」の` と `改善支援を` が別々の文節と判定され、`改善支援を` が丸ごと次の行へ送られていました。その結果、`の` の後に不自然な空白が空いていました。

```css
/* 修正後 */
body{ word-break:normal; line-break:strict; overflow-wrap:anywhere; }
h1,h2,h3,h4{ word-break:auto-phrase; }
```

- **本文**：ブラウザ標準の禁則処理で折り返します。`line-break:strict` を追加し、小書き文字（っ・ゃ・ゅ・ょ）や長音符が行頭に来ないようにしています
- **見出し**：`auto-phrase` を残しました。短文では文節折り返しが読みやすいためです
- ヒーローとCTAボタンの手動改行（`class="pw"`）は従来どおり動作します

この修正は**LP全体の本文に効きます**。FAQ以外の本文でも同じ現象が起きていたため、まとめて解消されています。

### ①について

「代表」という肩書を外し、直後の実績セクションにある「**このプログラムを設計した人**」と呼応する形にしました。読者は肩見出しを見た時点で「この人が書いている」と分かり、次のセクションでその人物の経歴を読む流れになります。役職を名乗らずに、書き手の立場だけを示せています。

### ②について

ご指摘のとおりです。「次の本番へ向かってほしくない」は、**次に向かうことを前提**にした言い方でした。婚活を止めている人、休んでいる人を含めるなら、抱える気持ちそのものを否定する形が正しくなります。短くなったぶん、一文としても強くなりました。

### ③について

「＝」を使うことで、**間違った等式を明確に否定する**構造が視覚的に伝わります。文字数も減り、リズムが良くなりました。
